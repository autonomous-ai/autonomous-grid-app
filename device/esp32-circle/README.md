# Grid Panel — ESP32 firmware

The device half of the Grid Panel. A round 466×466 AMOLED that shows what the agents on **one computer**
are doing and lets you speak to them, over a **USB cable and nothing else**.

**Board:** Waveshare ESP32-S3-Touch-AMOLED-1.75 — ESP32-S3R8, 466×466 round CO5300 over QSPI, CST9217
touch (mounted 180° to the panel), 8 MB octal PSRAM, 16 MB flash with two OTA slots, ES8311 codec with
microphone and speaker.

The wire format is `docs/panel-protocol.md` at the repo root. It is normative and it is implemented
**twice with no shared code** — `main/panel_frame.c` here, `lib/infrastructure/panel/panel_frame.dart` in
the app — so the document is the only place the two halves agree by construction rather than by
coincidence. Read it before changing anything that goes on the cable.

## Build

```bash
source ~/esp/esp-idf/export.sh        # ESP-IDF 5.5 or newer
idf.py set-target esp32s3
idf.py build
idf.py -p /dev/cu.usbmodem* flash
```

Then, to make the app carry this image:

```bash
scripts/sync_panel_firmware.sh        # from the repo root
```

> ⚠️ **Order matters, every time: sync the image in → rebuild the app → flash the device → start the app.**
> The app offers the `.bin` inside its BUILT BUNDLE, and the version comparison has no direction — an app
> whose bundle predates your build will quietly flash the panel *backwards* within seconds of seeing it,
> and `idf.py flash` will have said `Done`. See docs/panel-protocol.md, "Firmware update".

## Test the codec without a board

```bash
device/esp32-circle/scripts/test_frame.sh     # from the repo root
```

Compiles `main/panel_frame.c` with a plain host compiler and runs it against
`test/vectors/panel_frame.txt` — **the repo's file, not a copy under this directory.** Those vectors are
generated by `scripts/gen_panel_vectors.py`, a *third* implementation written from the spec rather than
transcribed from either side, and the Dart half asserts against the same file. A copy here would let this
side drift and still pass, which is the one thing the shared file exists to prevent.

The first assertion is `CRC16("123456789") == 0x29B1`. A port that fails only that has the wrong CRC
variant, not a wrong loop — several 16-bit CRCs share the `0x1021` polynomial.

## Which USB port

The board presents two, and they are not interchangeable:

| | | |
|---|---|---|
| the console | UART bridge | logs, `idf.py monitor` |
| **the protocol** | **USB-Serial-JTAG, `303a:1001`** | the SoC's own peripheral — this one |

`sdkconfig.defaults` sets `CONFIG_ESP_CONSOLE_SECONDARY_NONE=y`, and that line is load-bearing. IDF's
default mirrors the console onto the native port byte for byte, straight into the middle of the protocol
stream. Note the shape of the fix: writing `CONFIG_ESP_CONSOLE_SECONDARY_USB_SERIAL_JTAG=n` does **not**
deselect a Kconfig choice — it does nothing at all, which looks exactly like a fix. Check the *generated*
`sdkconfig`.

## What this is, and what it came from

It is `autonomous-code/apps/esp32-circle` — the reference firmware for this same board — with the network
taken out and the message layer replaced. The reference talks to a cloud backend over WiFi + WebSocket +
E2EE; **here the cable is the authorization and there is no network at all.**

Almost everything under `main/ui/` is byte-for-byte the reference's, verified with `diff` rather than by
eye. That is a decision with a measurement behind it: the previous attempt at this port hand-rewrote
`ui_screens.c` at 1483 lines against the reference's 7300, and *everything byte-identical behaved while
everything hand-written stuttered or was missing*. So the rule for this directory is **take the file and
delete what has no use here — do not rewrite it.**

Copied verbatim: `ui/touch.{c,h}` (the whole gesture layer), `ui/display.{c,h}` (the CO5300 init sequence
is verbatim from Waveshare), `ui/icons_*.c`, `ui/geist_*.c`, `ui/spinner_spokes.{c,h}`, `board/*`,
`audio_capture.c`, `ram_telemetry.c`, `device_mac.c`.

Written for the cable: `panel_frame.c` (framing), `panel_link.c` (USB-Serial-JTAG transport),
`panel_client.c` (the message layer), `voice.c` (PCM straight out as `0x02` frames), `fw_update.c`
(update over the cable). Each replaces something that assumed a socket.

Cut, each because the question it answers cannot arise here: provisioning, the setup chooser, pairing, the
E2EE handshake, the WiFi picker, Settings and the gear that was its only door, the Machines wheel, the
3×3 pattern lock, the Model/Effort picker, the voice quota, the OTA boot-mode screen, and URL-download
OTA. The carousel is now the Overview plus one tile per project.

## Notes worth reading before changing something

- **`main/panel_frame.c` must stay free of ESP-IDF headers.** The moment it includes one, the host test
  stops building and the only cheap check on the wire format goes with it.
- **Three numbers are one decision** — the app's 16 KB credit window, `PROGRESS_EVERY` (one 8192 B slice)
  and `USJ_RX_BUF` (32 KB). The S3's USB-Serial/JTAG has *no back-pressure* and drops what does not fit
  without telling either side. Getting this wrong wrote 0 of 1,342,160 bytes with no error anywhere.
- **There is no LED ring on this board.** The mockups say the LED is the loading cue; they are wrong for
  this hardware. The Working screen draws no spinner — the ticking elapsed time and the rotating gerund
  are the liveness cue. `spinner_spokes.c` is used only for voice "Sending…" and the boot/update waits.
- **The voice cap is 60 seconds**, matching what the app enforces. The mockups still say 10 minutes;
  `docs/panel-protocol.md` is the normative one.
- **`sdkconfig` is generated and gitignored, and it wins over `sdkconfig.defaults`.** The top-level
  `CMakeLists.txt` stamps the defaults' hash beside it so a change re-seeds instead of being silently
  dropped. Read the note there before "simplifying" it away — that gap cost the reference two weeks.
